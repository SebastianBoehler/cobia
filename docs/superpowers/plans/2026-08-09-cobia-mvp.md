# Cobia MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an X Layer RFQ market in which competing solvers submit private stablecoin-allocation routes, deterministic policy code exposes verified quote summaries, Agentic Wallet pays only the selected winner, and a constrained contract executes the revealed Aave V3 supply.

**Architecture:** A Next.js application owns request orchestration, PostgreSQL persistence, OKX data ingestion, and x402 settlement. Shared TypeScript schemas define policies, snapshots, bundles, and verdicts; two independent solvers consume one immutable snapshot. Foundry contracts commit provenance and restrict execution to a fixed Aave adapter.

**Tech Stack:** Node.js 22+, pnpm 11.20.0, Next.js 16.3.0, React 19.2.8, TypeScript 6.0.3 (latest compatible with Next's ESLint parser), Zod 4.4.3, Viem 2.55.11, OpenAI 7.4.0, `@okxweb3/mpp` 0.1.0, Drizzle ORM 0.45.2, PostgreSQL, Vitest 4.1.10, Solidity 0.8.30, Foundry.

## Global Constraints

- Brand name is `Cobia`; never expose `ProofMarket` in user-facing copy.
- Apply the light-first tokens, route-thread motif, copy rules, and trusted block
  registry from `../specs/2026-08-09-cobia-brand-product-design.md`.
- Execution policies target X Layer mainnet `196`; testnet `1952` is used for
  payment and provenance rehearsal because no authoritative Aave testnet market exists.
- The user intent is stablecoin hold versus Aave V3 supply only.
- Runtime data, payments, solver calls, transaction hashes, and Explorer links must be real; no mock or fallback data path exists.
- Integer strings represent token atoms; integer basis points represent rates and allocation; floating-point domain values are forbidden.
- One market snapshot is immutable and shared by both solvers.
- Complete bundles remain private until the selected solver's x402 payment
  settles; pre-payment APIs expose only sanitized `RouteQuote` values.
- Solver competition and verification precede payment. The winning payment is
  `100000` six-decimal atoms: `90000` to the selected solver and `10000` to Cobia.
- The LLM cannot provide target addresses, calldata, approvals, or executable amounts.
- All execution passes through `CobiaExecutor` and `AaveV3SupplyAdapter`.
- A file should remain below 300 lines; split by responsibility before crossing that limit.
- Testnet passes before mainnet. Mainnet principal is capped in deployment configuration and starts with the smallest practical value.
- If OKX chain-196 product discovery or x402 settlement fails at the feasibility gate, stop and revise the design; do not integrate an unapproved provider.

## Hard acceptance command

After all modules, a clean checkout must pass:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm --filter @cobia/contracts test
pnpm e2e:testnet
pnpm verify:deployment --network xlayer-mainnet
```

Expected: every command exits `0`; `e2e:testnet` prints payment, request,
bundle, and selection hashes; deployment verification prints chain ID `196` and
matching bytecode for all three mainnet contracts.

## Mainnet authorization boundary

The implementation plan prepares and verifies deployment. Before the first
mainnet transaction, show the exact contract addresses, token, Aave pool,
principal cap, solver prices, split recipients, and expected wallet actions.
Execute only after explicit user approval of that concrete mainnet run.
